# Телеметрия метеостанции

NodeMCU отправляет показания по Wi‑Fi на OpenWrt примерно раз в 30 секунд. Роутер ставит их в очередь и передаёт серверу на ПК партиями до 128 записей. Сервер отвечает HTTP 204 после сохранения партии в SQLite.

## Буфер

В кольце хранится до 28 800 записей не старше 10 дней. Одна запись занимает 32 байта. Файл кольца вместе с резервным слотом занимает до 921 632 байт, примерно 0,88 МиБ. Кроме него используются небольшой файл указателей и память процесса. Оба файла очереди должны лежать в `/tmp` на tmpfs. Перезапуск сервиса сохраняет очередь. При перезагрузке или обесточивании роутера она пропадает.

OpenWrt добавляет время при получении пакета. Синхронизация часов роутера нужна для правильных отметок и срока хранения. SQLite устраняет повторы по идентификатору станции, идентификатору загрузки NodeMCU и номеру измерения. При выключенном ПК NodeMCU продолжает отправлять. При потере связи самого NodeMCU с роутером прошивка удерживает только последний отсчёт до следующего измерения.

## Периоды графиков

В панели доступны 1 час, 6 часов, 24 часа, 7, 30, 90 и 180 дней, а также год (365 дней). По умолчанию открывается последний час. До суток отображаются исходные измерения. Для длинных периодов сервер группирует данные по интервалам от 15 минут до 12 часов и сохраняет на графике среднее, минимум и максимум CO₂. Годовой график берёт данные из истории SQLite на ПК, а буфер роутера хранит только очередь доставки.

Значок вкладки с облаком и солнцем находится в `server/static/favicon.png`.

## Запуск в домашней сети

1. На Windows создать Python-окружение и установить пакеты. Скопировать `server/config.example.json` в `server/config.json`, задать порт, сетевой адрес и случайный токен. Для первоначальной проверки запустить сервер вручную.

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r server/requirements.txt
   .\.venv\Scripts\python.exe server/server.py --config server/config.json
   ```

   На ПК страница доступна по `http://localhost:8780/`. При привязке к конкретному сетевому адресу сервер дополнительно слушает `127.0.0.1` на том же порту. Для приёма пакетов открыть TCP 8780 на ПК только для нужной локальной сети или адреса роутера. Закрепить адрес ПК в DHCP. После проверки скрипт `server/register-startup.ps1` регистрирует задачу Windows для запуска сервера после входа в учётную запись, из которой запущен скрипт. Первая попытка выполняется через 30 секунд после входа. Затем Планировщик повторяет запуск каждые две минуты, если сервер завершился. При необходимости другую учётную запись можно указать параметром -LogonUser. Указать абсолютный путь к `.venv\Scripts\python.exe`. Задача работает от LOCAL SERVICE. Этой учётной записи нужен доступ на чтение и запуск приложения с Python-окружением и на запись в каталог базы.

2. На OpenWrt используются уже установленные `uhttpd`, `ucode` с модулем `fs`, `curl`, `flock`, `jsonfilter` и `jshn`. Из `router/openwrt/native` скопировать `relay.uc`, `forward` и каталог `www` в `/usr/lib/meteo-relay/`. Дать файлу `www/v1/samples` права 0755, а каталоги и остальные файлы сделать доступными на чтение для `nobody`. Создать ссылку `/usr/lib/meteo-relay/settings.json` на `/tmp/meteo-relay-config/settings.json`. Скопировать `native/meteo-relay` в `/etc/init.d/meteo-relay` с правами 0755 и `router/openwrt/meteo.example` в `/etc/config/meteo`. Указать LAN-адрес роутера, URL ПК и установить `enabled 1`. Сохранить общий токен в `/etc/meteo.token` с владельцем `nobody` и правами 0600. Затем выполнить `/etc/init.d/meteo-relay enable` и `/etc/init.d/meteo-relay start`. Отдельный экземпляр `uhttpd` принимает телеметрию через CGI. Скрипт `forward` отправляет партии через `curl` и подтверждает их только после HTTP 204 от сервера.

3. В проекте NodeMCU скопировать `src/telemetry/meteo_secrets.h.example` в `src/telemetry/meteo_secrets.h`. Указать SSID сети 2,4 ГГц, пароль, URL роутера вида `http://<IP-роутера>:8781/v1/samples` и тот же токен. Выставить `METEO_ENABLE_WIFI 1` в `src/config.h`, сверить `METEO_STATION_ID` с настройкой OpenWrt и собрать прошивку. Локальный заголовок с паролем исключён из Git.

HTTP предназначен для доверенной домашней сети. Токен защищает приём от случайных запросов и передаётся внутри этой сети. Панель графиков доступна с адресов, которым разрешено подключаться к серверу.

Для обнаруженных адресов ПК `192.168.1.50` и шлюза `192.168.1.1` подготовлены локальные `server/config.json`, `router/openwrt/meteo.local` и `router/token`. Они исключены из Git. Роутер отправляет данные на `http://192.168.1.50:8780/`. Значение токена для прошивки берётся из локального файла `router/token`.

## Проверка

- Из корня проекта **`.\.venv\Scripts\python.exe tests/integration.py`** проверяет приём партий, авторизацию, исходные отметки времени, отсутствие дублей, периоды графиков и сохранность SQLite после перезапуска.
- Необязательный аргумент интеграционного теста — путь к установленному модулю Node.js Playwright с Chromium. Он включает проверку отрисовки, переключения периода и мобильной раскладки.
- После подключения оборудования выключить ПК на 10 минут, затем включить. В графике должно появиться около 20 точек со временем их получения роутером.

## Текущее развёртывание

- NodeMCU на COM5 прошита с `METEO_ENABLE_WIFI=1`. Настройки Wi‑Fi используются из локального заголовка. В SQLite получены реальные температура, влажность, давление и CO₂.
- На Qihoo 360T7 с OpenWrt 25.12.6 включён автозапуск `meteo-relay`. Отдельный `uhttpd` слушает `192.168.1.1:8781`. Рабочая очередь остаётся в `/tmp/meteo-queue/meteo-1/` и совместима с прежней Go-версией. Скрипты занимают 11 107 байт (10,8 КиБ), суммарный RSS постоянных процессов при замере составил около 2,0 МиБ. Кратковременные процессы `ucode`, `curl` и буфер учитываются отдельно. Старый Go-бинарник удалён с роутера после проверки новых записей в SQLite.
- На Windows после входа пользователя в систему сервер запускается задачей `Meteo Telemetry` от LOCAL SERVICE с локальным Python в `.runtime`. Правило `MeteoTelemetry-OpenWrt` разрешает обращения от роутера на `192.168.1.50:8780`. Страница графиков на ПК открывается по `http://localhost:8780/`.
- Чтобы NodeMCU продолжала передавать при выключенном ПК, ей нужно питание, которое не отключается вместе с ПК.

Локальные тесты очереди, HTTP и графиков в Chromium прошли. Проверены сборки прошивки по умолчанию, с Wi‑Fi и датчиками и с одним Wi‑Fi. Задача Windows проверена запуском через Планировщик.

При контролируемой остановке метеосервера роутер принял одну реальную запись. После повторного запуска сервера измерение `seq=8` появилось в SQLite с исходным временем `16:03:39.462`, а очередь на роутере опустела. Полное выключение ПК во время проверки не выполнялось.
